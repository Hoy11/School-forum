# 师生交流论坛系统开发文档

## 1. 系统概述

### 1.1 系统定位与目标
师生交流论坛是一个面向教师和学生的在线交流平台，旨在提供一个高效、便捷的师生互动环境。系统支持用户注册登录、发布帖子、回复评论、共享资源等基本功能，为师生之间的学术交流和日常互动提供便利。

### 1.2 系统架构
- 前端：Vue3 + Element Plus + Axios
- 后端：SpringBoot3 + MyBatis-Plus
- 数据库：MySQL8
- 构建工具：Maven + npm
- 版本控制：Git

## 2. 角色分配

系统包含以下三种角色：

1. **管理员**：负责整个论坛的管理，包括版块管理和内容管理
2. **教师**：教师用户，可以发布教学资源、参与讨论，可被任命为版主
3. **学生**：学生用户，可以浏览资源、参与讨论，可被任命为版主

## 3. 功能模块划分

系统分为以下六大功能模块：

1. **用户管理模块**：注册、登录、信息管理、个人资料维护（头像、个性签名、个人简介等）
2. **版区管理模块**：版区创建、编辑、删除
3. **帖子管理模块**：帖子发布、编辑、删除、查询
4. **评论管理模块**：评论发布、删除、查询
5. **资源管理模块**：资源上传、下载、分类管理
6. **系统管理模块**：系统通知、举报处理

## 6. 功能流程设计

### 6.1 用户注册与登录流程

1. 用户注册
   - 用户填写注册信息（用户名、密码、确认密码、角色、联系方式等）
   - 系统验证用户信息的合法性
   - 将用户信息存入数据库，角色默认为学生，设置默认头像
   - 注册成功，跳转到登录页面

2. 用户登录
   - 用户输入用户名和密码
   - 系统验证用户身份信息
   - 登录成功，根据用户角色跳转到相应界面
   - 登录失败，提示错误信息

3. 个人资料维护
   - 用户进入个人资料页面
   - 上传/修改头像
   - 编辑个性签名和个人简介
   - 保存修改，更新数据库信息

4. 用户管理（管理员）
   - 管理员可查看所有用户列表
   - 可以添加新用户
   - 可以修改用户基本信息
   - 可以启用/禁用用户账号
   - 可以删除用户账号

### 6.2 帖子发布与回复流程

1. 发布帖子
   - 用户选择版区
   - 填写帖子标题和内容
   - 点击发布，系统验证内容合法性
   - 将帖子信息存入数据库
   - 发布成功，跳转到帖子详情页

2. 回复帖子
   - 用户在帖子详情页下方输入回复内容
   - 点击回复，系统验证内容合法性
   - 将回复信息存入数据库
   - 回复成功，刷新帖子详情页

### 6.3 资源上传与下载流程

1. 上传资源
   - 用户选择资源分类
   - 填写资源名称、描述等信息
   - 选择要上传的文件
   - 点击上传，系统验证文件合法性
   - 将资源信息存入数据库，文件保存到服务器
   - 上传成功，跳转到资源列表页

2. 下载资源
   - 用户浏览资源列表
   - 点击下载按钮
   - 系统验证用户权限
   - 下载成功，文件下载到用户本地

### 6.4 版主管理流程

1. 版主任命
   - 管理员在版区管理页面选择指定版区
   - 点击"版主管理"，进入版主管理页面
   - 从教师或学生用户列表中选择用户作为版主
   - 确认任命，系统记录任命信息
   - 任命成功，相关用户获得对应版区的版主权限

2. 版主管理职责
   - 任命为版主的教师或学生用户登录系统，进入所负责的版区
   - 对版区内帖子进行管理（加精/删除等）
   - 对版区内评论进行管理（审核/删除等）
   - 处理用户举报信息

3. 版主权限取消
   - 管理员在版主管理页面选择要取消权限的版主
   - 点击"取消任命"，系统更新版主状态
   - 权限取消成功，用户失去版主权限，但保留原有的教师或学生角色权限

## 7. 安全与权限设计

1. 用户密码加密存储，采用BCrypt加密算法
2. 基于JWT（JSON Web Token）的身份验证机制 
3. 基于角色的简单访问控制（管理员、教师、学生）
4. 前后端分离的跨域安全配置
5. 敏感操作二次确认
6. 防SQL注入、XSS攻击和CSRF攻击处理
7. 文件上传类型限制和验证

## 8. 系统测试计划

## 十一、前端请求工具使用指南

### 1. HTTP请求封装概述

本项目使用`request.js`工具封装了基于Axios的HTTP请求，提供了统一的接口调用方式和错误处理机制。该工具位于`src/utils/request.js`，具有以下特性：

1. **自动携带Token**: 在请求头中自动添加token，简化认证流程
2. **统一错误处理**: 自动处理常见HTTP错误和业务错误
3. **定制化消息提示**: 支持自定义成功/错误提示
4. **灵活的回调机制**: 支持成功/错误回调函数
5. **简化的API方法**: 封装了GET、POST、PUT、DELETE等常用请求方法

### 2. 请求配置选项

`request.js`支持以下配置选项：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|-------|------|
| showDefaultMsg | boolean | true | 是否显示默认的成功/错误提示 |
| successMsg | string | - | 自定义成功提示消息 |
| errorMsg | string | - | 自定义错误提示消息 |
| onSuccess | Function | - | 成功回调函数，参数为响应数据 |
| onError | Function | - | 错误回调函数，参数为错误信息 |

#### 4.3 使用回调函数

**重要：** 请求成功或失败的后续操作应该在回调函数中处理，而不是在Promise的then/catch中。这样可以确保处理逻辑与请求配置放在一起，更加清晰和集中。

```javascript
// 推荐方式：使用回调函数处理成功/失败逻辑
request.post('/api/users', userData, {
  successMsg: '用户创建成功',
  onSuccess: (data) => {
    // 成功后的业务逻辑处理
    console.log('创建的用户ID:', data.id)
    router.push(`/user/${data.id}`)
    // 更新状态或执行其他操作
    userStore.addUser(data)
  },
  onError: (error) => {
    // 错误处理逻辑
    console.error('创建用户失败:', error)
    if (error.code === '1001') {
      // 用户名已存在
      ElMessage.warning('用户名已被使用，请更换')
      // 可以直接修改表单状态
      userForm.username = ''
    }
  }
})

// 不推荐：混合使用回调和Promise
request.post('/api/users', userData, {
  successMsg: '用户创建成功'
})
  .then(data => {
    // 不推荐在这里处理成功逻辑
    // 应该使用onSuccess回调
  })
  .catch(error => {
    // 不推荐在这里处理错误逻辑
    // 应该使用onError回调
  })
```

与Promise链不同，回调函数可以直接访问组件内的状态和方法，无需额外的闭包或引用。**所有的后续处理逻辑应集中在回调函数中**，而不是分散在Promise链中。

#### 4.4 混合使用

可以组合使用上述配置，但应保持请求后的处理逻辑在回调函数中：

```javascript
request.post('/api/login', loginData, {
  successMsg: '登录成功，正在跳转...',
  errorMsg: '登录失败，请检查用户名和密码',
  showDefaultMsg: true,
  onSuccess: (data) => {
    // 保存用户信息和token
    store.commit('setUserInfo', data)
    // 跳转到首页
    router.push('/dashboard')
    // 其他所有后续操作都应在此处理
    localStorage.setItem('lastLoginTime', new Date().toISOString())
  },
  onError: (error) => {
    // 所有错误处理逻辑都应在此处理
    loginForm.password = ''
    // 记录登录失败次数
    failedAttempts.value++
    if (failedAttempts.value >= 3) {
      ElMessage.warning('多次登录失败，请稍后再试')
      loginDisabled.value = true
      setTimeout(() => {
        loginDisabled.value = false
        failedAttempts.value = 0
      }, 30000)
    }
  }
})
// 不要在这里添加 .then() 或 .catch() 处理
```

### 5. 在组件中的实际应用

以下是在Vue组件中使用request工具的完整示例，注意所有后续处理都在回调函数中：

#### 5.1 用户登录示例

```javascript
// Login.vue
import { ref, reactive } from 'vue'
import { useRouter } from 'vue-router'
import { useUserStore } from '@/store/user'
import request from '@/utils/request'

export default {
  setup() {
    const router = useRouter()
    const userStore = useUserStore()
    
    const loginForm = reactive({
      username: '',
      password: ''
    })
    
    const loading = ref(false)
    const errorCount = ref(0)
    
    const handleLogin = () => {
      if (!loginForm.username || !loginForm.password) {
        ElMessage.warning('请输入用户名和密码')
        return
      }
      
      loading.value = true
      
      // 使用回调函数处理所有后续逻辑
      request.post('/api/login', loginForm, {
        successMsg: '登录成功',
        errorMsg: '登录失败，请检查用户名和密码',
        onSuccess: (data) => {
          // 所有成功后的操作都在这里处理
          userStore.setUserInfo(data)
          router.push('/')
          console.log('登录成功:', data)
        },
        onError: (error) => {
          // 所有错误处理都在这里
          console.error('登录失败:', error)
          loginForm.password = ''
          errorCount.value++
        },
        // 这个函数无论成功失败都会执行，类似于finally
        onComplete: () => {
          loading.value = false
        }
      })
      
      // 不要使用 .then 或 .catch 或 .finally 处理后续逻辑
      // 所有逻辑都应放在上面的回调函数中
    }
    
    return {
      loginForm,
      loading,
      handleLogin
    }
  }
}
```
