# 版区模块文档

## 1. 模块概述

### 1.1 模块定位与目标
版区模块是师生交流论坛系统的核心组织单元，为系统提供内容的分类管理与组织结构。该模块负责版区的创建、编辑、管理以及版主的任命与管理，是帖子、评论等内容的归属容器，为用户提供有序的内容浏览与交流环境。

### 1.2 功能特点
- 多层次的版区管理（创建、编辑、删除、状态控制）
- 版主管理系统（任命、权限分配、状态管理）
- 版区内容统计与分析
- 前后台一体化的版区浏览界面
- 权限分级控制的管理机制

## 3. 后端设计与实现

### 3.1 版区管理核心功能

版区管理的核心功能由`SectionService`和`SectionController`实现，主要包括版区的CRUD操作及状态管理。

#### 3.1.1 版区创建

```java
// SectionService.java
public boolean addSection(Section section) {
    // 检查版区名称是否存在
    if (sectionMapper.selectOne(
            new LambdaQueryWrapper<Section>()
                .eq(Section::getSectionName, section.getSectionName())
        ) != null) {
        throw new ServiceException("版区名称已存在");
    }
    
    // 设置初始值
    section.setCreateTime(new Date());
    if (section.getStatus() == null) {
        section.setStatus(1); // 默认状态为正常
    }
    
    return sectionMapper.insert(section) > 0;
}
```

版区创建流程：
1. 检查版区名称唯一性，防止重复创建
2. 设置创建时间和默认状态
3. 将版区信息持久化到数据库

#### 3.1.2 版区查询与列表

版区查询功能支持多条件分页查询，包括按名称模糊查询和状态筛选：

```java
// SectionService.java
public IPage<Section> listSections(Integer current, Integer size, String sectionName, Integer status) {
    LambdaQueryWrapper<Section> queryWrapper = new LambdaQueryWrapper<>();
    if (StringUtils.isNotBlank(sectionName)) {
        queryWrapper.like(Section::getSectionName, sectionName);
    }
    if (status != null) {
        queryWrapper.eq(Section::getStatus, status);
    }
    queryWrapper.orderByDesc(Section::getCreateTime);
    
    return sectionMapper.selectPage(new Page<>(current, size), queryWrapper);
}
```

#### 3.1.3 版区状态管理

系统提供了版区状态的控制功能，允许管理员启用或禁用特定版区：

```java
// SectionService.java
public boolean updateSectionStatus(Long sectionId, Integer status) {
    // 检查版区是否存在
    if (sectionMapper.selectById(sectionId) == null) {
        throw new ServiceException("版区不存在");
    }
    
    Section section = new Section();
    section.setId(sectionId);
    section.setStatus(status);
    section.setUpdateTime(new Date());
    
    return sectionMapper.updateById(section) > 0;
}
```

### 3.2 版主管理功能

版主管理是版区模块的重要组成部分，由`SectionModeratorService`和`SectionModeratorController`实现。

#### 3.2.1 版主任命

```java
// SectionModeratorService.java
public void appointModerator(ModeratorDTO moderatorDTO, Long appointBy) {
    // 检查版区是否存在
    sectionService.getSectionById(moderatorDTO.getSectionId());
    
    // 检查用户是否存在
    User user = userService.getUserById(moderatorDTO.getUserId());
    
    // 检查用户是否已经是该版区的版主
    if (moderatorMapper.selectOne(
            new LambdaQueryWrapper<SectionModerator>()
                .eq(SectionModerator::getSectionId, moderatorDTO.getSectionId())
                .eq(SectionModerator::getUserId, moderatorDTO.getUserId())
                .eq(SectionModerator::getStatus, 1)
        ) != null) {
        throw new ServiceException(user.getUsername() + " 已经是该版区的版主");
    }
    
    SectionModerator moderator = new SectionModerator();
    moderator.setSectionId(moderatorDTO.getSectionId());
    moderator.setUserId(moderatorDTO.getUserId());
    moderator.setAppointTime(new Date());
    moderator.setAppointBy(appointBy);
    moderator.setStatus(moderatorDTO.getStatus() != null ? moderatorDTO.getStatus() : 1);
    moderator.setRemark(moderatorDTO.getRemark());
    
    if (moderatorMapper.insert(moderator) <= 0) {
        throw new ServiceException("任命版主失败");
    }
}
```

版主任命流程：
1. 验证版区和用户的存在性
2. 检查用户是否已经是该版区的版主，避免重复任命
3. 创建版主记录并设置相关信息（任命时间、任命人等）
4. 将版主信息持久化到数据库

### 3.3 扩展查询功能

版区模块还提供了一些扩展查询功能，如版区搜索：

```java
// SectionService.java
public List<Section> searchSections(String keyword, Integer limit) {
    LambdaQueryWrapper<Section> queryWrapper = new LambdaQueryWrapper<>();
    if (StringUtils.isNotBlank(keyword)) {
        queryWrapper.like(Section::getSectionName, keyword)
                  .or()
                  .like(Section::getDescription, keyword);
    }
    queryWrapper.eq(Section::getStatus, 1)
               .orderByDesc(Section::getCreateTime);
    
    if (limit != null) {
        Page<Section> page = new Page<>(1, limit);
        return sectionMapper.selectPage(page, queryWrapper).getRecords();
    } else {
        return sectionMapper.selectList(queryWrapper);
    }
}
```

## 5. 数据交互流程

### 5.1 版区创建流程

1. **前端**：用户在后台管理页面点击"新增版区"按钮，弹出版区创建表单
2. **前端**：用户填写版区名称、描述等信息，点击"确定"按钮
3. **前端**：表单数据通过POST请求发送到后端接口`/section/add`
4. **后端**：`SectionController.addSection`方法接收请求，调用`SectionService.addSection`处理
5. **后端**：检查版区名称是否已存在，验证其他字段合法性
6. **后端**：设置默认值（创建时间、状态），将数据插入数据库
7. **后端**：返回操作结果
8. **前端**：根据返回结果显示成功/失败提示，成功后刷新版区列表

### 5.2 版主任命流程

1. **前端**：管理员在版区管理页面点击"版主管理"按钮，进入版主管理界面
2. **前端**：点击"添加版主"按钮，弹出版主选择表单
3. **前端**：通过远程搜索选择用户，填写备注信息
4. **前端**：提交表单，发送POST请求到`/moderator/appoint`接口
5. **后端**：`SectionModeratorController.appointModerator`方法接收请求
6. **后端**：验证版区和用户存在性，检查是否已是版主
7. **后端**：创建版主记录，设置任命时间、任命人等信息
8. **后端**：返回操作结果
9. **前端**：根据返回结果显示成功/失败提示，成功后刷新版主列表

### 5.3 版区详情查询流程

1. **前端**：用户点击某个版区卡片，路由跳转到版区详情页
2. **前端**：通过路由参数获取版区ID
3. **前端**：同时发起多个请求：
   - 请求版区基本信息：`/section/{id}`
   - 请求版主列表：`/moderator/section/{sectionId}`
   - 请求帖子统计：`/post/section/stats/{sectionId}`
   - 请求帖子列表：`/post/page`（带分页和筛选参数）
4. **后端**：对应的控制器方法处理各个请求，返回数据
5. **前端**：接收返回数据，更新页面显示
6. **前端**：用户可进行后续操作（查看帖子、发布帖子、筛选帖子等）

## 6. 权限控制

### 6.1 版区管理权限

版区模块实现了基于角色的权限控制：

1. **管理员**：拥有所有版区的完全管理权限
   - 可以创建、编辑、删除任何版区
   - 可以控制版区状态（启用/禁用）
   - 可以任命和移除任何版主

2. **版主**：拥有其管理版区的部分管理权限
   - 可以查看和编辑其管理的版区信息
   - 可以管理其版区内的帖子（加精、删除等）
   - 不能创建或删除版区

3. **普通用户**：仅有浏览权限
   - 可以查看所有启用状态的版区
   - 可以在版区内发布帖子和评论
   - 没有版区管理权限

## 7. 异常处理

### 7.1 业务异常

版区模块定义了业务操作中可能出现的异常情况，并进行了适当处理：

```java
// 检查版区名称是否存在
if (sectionMapper.selectOne(
        new LambdaQueryWrapper<Section>()
            .eq(Section::getSectionName, section.getSectionName())
    ) != null) {
    throw new ServiceException("版区名称已存在");
}
```

常见业务异常包括：
- 版区名称重复
- 操作不存在的版区
- 重复任命版主
- 无权限操作特定版区

### 7.2 前端异常处理

前端使用统一的请求工具处理异常，并显示友好的错误提示：

```javascript
// 处理状态变更
const handleStatusChange = async (status) => {
  try {
    statusLoading.value = true
    await request.put(`/section/${sectionId.value}/status?status=${status}`, null, {
      successMsg: `板块已${status === 1 ? '启用' : '禁用'}`,
      onSuccess: () => {
        // 更新本地状态
        section.value.status = status
      },
      onError: () => {
        // 如果失败，回滚状态
        section.value.status = status === 1 ? 0 : 1
      }
    })
  } catch (error) {
    console.error('更新板块状态失败:', error)
  } finally {
    statusLoading.value = false
  }
}
```
